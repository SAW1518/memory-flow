## Project Overview

Memory Flow — a typing practice app where users register vocabulary words and practice typing them repeatedly. Built with Next.js 16 (App Router), React 19, Tailwind CSS 4, and Clerk for authentication. Data is stored in PostgreSQL via **Prisma ORM v7** with the `@prisma/adapter-pg` driver adapter.

## Commands

- **Dev server:** `pnpm dev`
- **Build:** `pnpm build`
- **Lint:** `pnpm lint` (ESLint with next/core-web-vitals + typescript configs)
- **Format:** `pnpm format` (Prettier with tailwindcss plugin)
- **Format check:** `pnpm format:check`
- **Setup (fresh clone):** `pnpm setup` (installs deps + generates Prisma client)
- **Prisma generate:** `pnpm prisma generate` (regenerate types after schema changes)
- **Prisma migrate:** `pnpm prisma migrate dev --name describe_change` (create + apply a migration)
- **Prisma pull:** `pnpm prisma db pull` (introspect existing DB into schema)
- **Prisma studio:** `pnpm prisma studio` (visual DB browser)
- **DB setup (local):** `pnpm db:setup` (starts Docker Postgres, applies migrations, seeds)
- **DB start/stop:** `pnpm db:start` / `pnpm db:stop`
- **DB reset:** `pnpm db:reset` (destroys the Docker volume and rebuilds from scratch)
- **Seed:** `pnpm prisma db seed` (Prisma v7 no longer auto-seeds after migrate — run explicitly)

Package manager is **pnpm** (enforced via `preinstall` script — npm/yarn will fail). A `postinstall` hook auto-runs `prisma generate` after `pnpm install`.

## Architecture

### Routing (App Router)

- `/` — Home page (server component): word registration form + card grid of saved words
- `/word?practice=<word>` — Typing practice page (client component): type a word N times to complete
- `/word` has its own layout with a back-navigation header

### Key Directories

- `app/lib/` — Server-side data layer and shared types
  - `prisma.ts` — Prisma client singleton (uses `@prisma/adapter-pg` + `pg` Pool)
  - `data.ts` — Database queries (`getWords`) using Prisma, marked `'use server'`
  - `actions.ts` — Server Actions for form submissions (e.g., `createInvoice`)
  - `action.typs.ts` — Zod schemas for form validation
- `app/ui/` — Reusable UI components organized by concern (`card/`, `cursor/`, `navbar/`, `logo/`, `icons/`)
- `proxy.ts` — Clerk middleware configuration (despite the filename, this is the Next.js middleware)

### Database

Uses **Prisma ORM v7** with the `@prisma/adapter-pg` driver adapter and `pg` connection pool.

- **Schema:** `prisma/schema.prisma` — single source of truth for DB models and types
- **Config:** `prisma.config.ts` — provides `DATABASE_URL` to Prisma CLI commands
- **Client:** `app/lib/prisma.ts` — singleton PrismaClient with pg Pool adapter
- **Types:** Auto-generated by Prisma into `@prisma/client` (import with `import type { GeneralWord } from '@prisma/client'`)
- **Env var:** `DATABASE_URL`
- **Models:** `GeneralWord` (maps to `general_words`), `UserWord` (maps to `users_words`)
- **Seed:** `prisma/seed.ts` inserts 15 words programmers commonly misspell (separate, occurred, receive, …) into `general_words`

#### Environments

- **Local:** Postgres 16 in Docker (`docker-compose.yml`, container `memoryflow-postgres`). `DATABASE_URL` in `.env` points at `localhost:5432/memoryflow`.
- **Production:** Neon (Serverless Postgres) provisioned through the Vercel Marketplace, connected to the `memory-flow` Vercel project. Vercel injects `DATABASE_URL` (pooled) and `DATABASE_URL_UNPOOLED` (direct) into Production/Preview.
- Prisma CLI does not auto-load `.env` in v7 — `prisma.config.ts` loads it via `import 'dotenv/config'`. Do not remove that import.

#### Modifying the database

1. Edit `prisma/schema.prisma`
2. Run `pnpm prisma migrate dev --name describe_the_change`
3. Run `pnpm prisma generate` — Prisma v7 does NOT regenerate the client automatically after migrate
4. Commit the migration files in `prisma/migrations/` to git

Never modify the DB manually — always change the schema first, then migrate.

#### Deploying migrations to production (Neon)

Run against the **unpooled** connection string (the pooled/pgbouncer URL can break migrations). Order matters: migrate before seed.

```sh
DATABASE_URL="<DATABASE_URL_UNPOOLED from Vercel>" pnpm prisma migrate deploy
DATABASE_URL="<DATABASE_URL_UNPOOLED from Vercel>" pnpm prisma db seed   # only when seed data changed
```

If you `export DATABASE_URL` instead, `unset DATABASE_URL` afterwards or later local commands will hit production.

### Auth

Clerk handles authentication. The root layout wraps everything in `ClerkProvider` with dark theme. Middleware in `proxy.ts` protects routes. Navbar shows sign-in/user buttons via Clerk components.

- **Development:** `pk_test_`/`sk_test_` keys (Clerk development instance). These are the only keys that work on `localhost` and `*.vercel.app`.
- **Production:** Clerk production instance bound to `memory-flow.dev` with `pk_live_`/`sk_live_` keys set in Vercel (Production environment). Live keys ONLY work on that domain. Its 5 CNAME records (`clerk`, `accounts`, `clkmail`, `clk._domainkey`, `clk2._domainkey`) live in Vercel DNS; status is visible in Clerk Dashboard → Configure → Domains.
- Dev and prod instances have separate user lists.

### Deployment

- **Hosting:** Vercel, project `memory-flow`, deploys from `main`.
- **Domain:** `www.memory-flow.dev` (apex redirects to www). DNS is on Vercel nameservers — manage records in Vercel → Domains → memory-flow.dev.
- **Env vars** (Vercel → Settings → Environment Variables): `DATABASE_URL` + `POSTGRES_*`/`DATABASE_URL_UNPOOLED` (injected by the Neon integration), `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`. Env changes require a redeploy; DNS changes do not.
- `postinstall` runs `prisma generate` during the Vercel build — no extra build config needed.

### Styling

Tailwind CSS 4 with `@tailwindcss/postcss`. Fonts: Inter and Outfit loaded via `next/font/google`. Dark theme throughout (neutral-800/900 backgrounds). Path alias `@/*` maps to project root.
